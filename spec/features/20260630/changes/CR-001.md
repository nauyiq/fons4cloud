# CR-001 gateway 认证优化与 admin 双层权限边界调整

> 功能标识：`admin-control-plane`
> 变更类型：契约变更
> SDD 等级：`S2`
> 文档状态：正式
> 创建日期：2026-07-08

## 1. 变更摘要

- 变更一句话说明：将 admin 接口权限边界调整为 gateway 粗粒度控制面准入 + admin-service 内部细粒度 RBAC，并优化 gateway 对业务免 Token URI 的运行期读取方式。
- 本次变更结论：admin 细粒度 `{domain}:{action}` 权限不作为 gateway 全局授权资源；gateway 负责校验 Token、动态免 Token 白名单，并复用框架 `@AuthenticationResource(authorities = "ADMIN")` 注册的控制面入口 authority，admin-service 负责管理员绑定、状态和功能权限。
- 是否建议新建 feature：否，原因是变更集中在既有 admin 控制面的安全链路和任务补充，不替换超过 70% 需求或核心数据模型。

## 2. 变更原因

- 用户诉求：gateway 原本认证逻辑需要优化；admin 接口需要走两层权限认证，一层是 gateway admin authority 控制，二层是 admin 内部 RBAC。
- 业务或技术背景：当前 `@AuthenticationResource` 同时被公共扫描器注册为 gateway 全局授权资源，又被 admin 拦截器作为内部 RBAC 权限声明使用，导致 admin 细粒度权限与 token authorities 混用，gateway 经 `/admin/services` 返回 `400002`。
- 不变更的影响：继续使用同一注解承载两层权限语义会导致控制面接口无法稳定经 gateway 访问，也容易把 admin 内部权限治理误配置成全局网关权限资源。

- 任务规划未完成项：T022，处理方式为追加 T023-T026 后再复检关闭。
- 历史 CR 未完成项：无。

- 技术设计与当前实现一致性：存在差异，当前实现中 admin Controller 使用 `@AuthenticationResource` 声明内部权限，`HttpAuthenticationResourceScanner` 会将 `services:view` 等细粒度权限注册到 `GLOBAL_AUTHORIZATION_RESOURCE`。
- 前置依赖：无。本 CR 不涉及持久化结构变更，不需要 DDL 证据。

## 4. 影响范围

- 需求影响：有，AC-007 的权限控制口径补充为入口准入和内部 RBAC 两层。
- 技术设计影响：有，需更新身份与权限治理、安全设计、技术决策、AC 映射和风险。
- 代码影响：有，涉及 `fons4cloud-gateway`、`fons4cloud-common-web` 扫描边界、`fons4cloud-admin` 安全注解与拦截器、admin Controller。
- 测试影响：有，需要覆盖 gateway 动态免 Token、framework `ADMIN` authority 准入、admin 内部 RBAC 和端到端经 gateway 调用。
- 接口/契约影响：有，`/admin/**` 经 gateway 的鉴权语义从细粒度业务权限改为由 `@AuthenticationResource(authorities = "ADMIN")` 注册的控制面入口权限，细粒度权限在 admin-service 内部完成。
- 权限/安全影响：有，本次变更属于权限边界修正，需要 S2 风险门禁复检。
- 兼容/回滚影响：有，回滚后仍会回到 gateway 依赖 `@AuthenticationResource` 注册的细粒度资源策略，可能再次出现 `400002`。

## 6. 技术设计影响

- API/RPC/消息影响：具体影响为 `/admin/auth/login` 等登录入口需要可通过 gateway 动态免 Token 白名单访问；其他 `/admin/**` 需要携带有效 Token，并通过 `@AuthenticationResource(authorities = "ADMIN")` 复用框架资源授权。
- 领域对象/业务规则影响：admin 内部 RBAC 继续使用 `admin_user`、`admin_role`、`admin_permission`；Controller 需要同时使用 `@AuthenticationResource(authorities = "ADMIN")` 表达 gateway 入口准入，使用 admin 专属 `@AdminPermission` 表达内部细粒度 RBAC，避免把 `{domain}:{action}` 注册为 gateway 全局资源。
- 状态流转影响：不适用，原因是草稿、发布、回滚状态机不变。
- 事务/一致性影响：不适用，原因是只调整认证授权链路，不改变数据库写入事务。
- 工具包/依赖影响：不适用，原因是不新增外部依赖。

## 8. 回归与回滚

- 回归风险：有，gateway 白名单动态读取若放行范围过宽会造成未授权访问；Token 中缺少框架 `ADMIN` authority 或接口未注册 `@AuthenticationResource(authorities = "ADMIN")` 会造成控制面不可访问。
- 回归验证范围：gateway 登录入口免 Token、非 `ADMIN` authority Token 被 gateway 拒绝、`ADMIN` authority Token 进入 admin-service、admin 内部 RBAC 拒绝缺少功能权限的管理员、具备两层权限后成功访问。
- 回滚方案：回滚本 CR 对 gateway 和 admin 注解拆分的实现，恢复原 `@AuthenticationResource` 注册逻辑；回滚前需确认控制面经 gateway 的访问风险。
- S2 风险门禁：需要，原因是本次变更涉及权限、安全和跨 gateway/admin/auth 的访问契约。
