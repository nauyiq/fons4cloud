## 4. 单 JAR 启动证据与阻塞

为避免连接生产或未知环境，使用本机 `18002` 端口和临时配置进行三次只读 smoke；每次失败后均停止本次创建的 Java 进程，未执行治理 API、DDL 或 DML。

1. 默认配置导入阶段因本机没有 Nacos，`nacos:datasource-admin.yaml` 不存在而退出。
2. 替换为隔离配置并禁用 Nacos、Redis/DataSource/MyBatis 自动装配后，现有 `ShardingSphereAutoConfiguration` 因 `@Bean` 方法级 `@Autowired` 与当前 Spring 启动校验不兼容而退出。
3. 仅为 Web/UI smoke 继续排除 ShardingSphere 后，公共 `WebAutoConfiguration` 的鉴权资源扫描器仍强制创建 Redisson，并连接 `127.0.0.1:6379`；连接被拒绝后退出。

因此没有将“继续裁剪生产鉴权与缓存栈后启动的空壳应用”记录为通过。该结果同时说明 admin-service 当前不能在完全无基础设施的机器上做完整进程 smoke；需要在 T020 的隔离环境中使用真实依赖验证。

## 5. T020 所需环境

继续关闭真实环境 Gate 前，至少需要：

- 非生产 Nacos 地址、独立 namespace/group 和测试账号；不得使用默认或生产 namespace。
- Redis 测试实例或独立数据库与明确 key prefix，并允许清理本次测试键。
- MySQL admin 测试库、当前结构和最小测试数据；禁止临时改生产结构。
- 可用 auth-service/Dubbo 注册信息、测试管理员账号和 `ADMIN_AUTH_CLIENT_SECRET`。
- 可访问的 gateway 与至少一个 Actuator 测试服务。
- 可清理的测试路由、IP 名单、授权资源和 OAuth Client，及外部修改制造漂移的权限。

2026-07-10 首轮验证时，当前进程环境中 `NACOS_SERVER`、`NACOS_NAMESPACE`、`NACOS_USERNAME`、`NACOS_PASSWORD`、`ADMIN_AUTH_CLIENT_SECRET`、`ADMIN_ENVIRONMENT_NAME` 均未设置；当时本机也没有 8848、6379、3306、8002 的监听服务。该项已被 2026-07-13 外部启动环境部分替代，最新结论见第 8 节。
