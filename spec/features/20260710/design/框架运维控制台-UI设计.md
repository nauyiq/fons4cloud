# 框架运维控制台 UI 设计契约

> 功能标识：`admin-operations-console-v2`  
> 状态：已确认  
> 设计方向：推荐 A——沉稳专业运维风格  
> 信息架构：能力工作区 + 统一变更中心  
> 确认依据：用户已确认推荐 A、单管理员使用、直接发布、单部署单环境以及基于旧版直接改造。

## 1. 设计目标

- 面向平台维护者提供高密度、低干扰、可审计的内部运维工作台。
- 首页优先呈现需要处理的异常、漂移、失败发布和待处理变更，而不是营销式指标大屏。
- 服务、网关、流量、访问控制和认证客户端分别形成能力工作区，所有写操作统一进入变更中心。
- Nacos、Redis、Actuator 和认证服务只作为数据来源或执行目标，不暴露成通用中间件管理台。
- 单个 admin-service 只展示一个明确环境，不提供环境切换器。

## 2. 视觉基线

### 2.1 色彩与层级

- 左侧导航：深石墨色背景，当前菜单使用品牌蓝强调；禁止高饱和渐变和大面积装饰。
- 主工作区：浅灰页面背景、白色内容面板、低对比边框。
- 状态色：正常为绿色、提醒为琥珀色、失败/高风险为红色、执行中为蓝色、未知为灰色。
- 高风险按钮只在发布、回滚和覆盖类动作中使用红色或警示色；只读动作使用中性按钮。
- 环境名称固定显示在顶栏，并与账号、权限信息分离。

### 2.2 信息密度

- 列表默认使用紧凑表格，不使用同质化卡片堆叠。
- 页面采用“标题与动作区 + 筛选区 + 主内容区 + 抽屉/详情区”结构。
- 长配置、差异和审计详情使用可滚动区域；不挤压主表格。
- 时间、状态、对象标识和 requestId 使用等宽或易扫描样式。

### 2.3 交互反馈

- 加载、空数据、无权限、依赖不可用、解析失败、数据漂移和执行失败必须具有不同文案和视觉状态。
- 所有失败反馈包含失败阶段、是否可重试以及 requestId；不直接展示后端堆栈。
- 发布和回滚必须经过差异预览与二次确认；执行后以服务端状态查询为准。
- Token、Secret、密码和敏感配置只显示掩码或“已设置/已变化”，不提供明文查看入口。

## 3. 全局布局

```text
┌───────────────────────────────────────────────────────────────┐
│ 深色侧栏                     │ 顶栏：环境 / 依赖状态 / 用户   │
│ - 运行概览                   ├───────────────────────────────┤
│ - 服务治理                   │ 页面标题、说明、主要动作       │
│ - 网关治理                   │ 筛选与状态摘要                 │
│ - 流量治理                   │                               │
│ - 访问控制                   │ 主表格 / 详情 / 编辑器         │
│ - 认证客户端                 │                               │
│ - 变更中心                   │                               │
│ - 审计追踪                   │                               │
└──────────────────────────────┴───────────────────────────────┘
```

- 侧栏宽度稳定，菜单按权限过滤；隐藏菜单不代替服务端鉴权。
- 顶栏始终展示当前环境名称及关键依赖总体状态。
- 移动端不作为主要使用场景；窄屏允许侧栏折叠，但不降低安全确认要求。

## 4. 页面契约

### 4.1 登录页

- 单列登录面板，展示产品名、当前环境和账号密码输入。
- 登录失败区分凭据错误、认证服务不可用和会话失效。
- 不提供注册、找回密码、社交登录或租户选择。

### 4.2 运行概览

- 第一视觉区域展示行动队列：失败发布、待确认执行、漂移资源、异常实例和依赖异常。
- 次级区域展示服务、治理资源、变更和审计的紧凑统计。
- 每个行动项均可跳转到对应资源、变更或审计详情。
- “正常零数量”和“依赖不可用导致未知”必须明确区分。

### 4.3 服务治理

- 服务列表支持名称、健康状态筛选；展示实例数、健康数、更新时间。
- 服务详情展示实例地址摘要、健康、元数据摘要和允许的只读探测动作。
- 探测必须选择明确实例和受控端点，不允许输入任意 URL。

### 4.4 网关治理

- 路由列表展示 routeId、URI 摘要、谓词、过滤器、顺序和当前状态。
- 详情同时提供结构化视图、原始 JSON 高级视图和关联变更历史。
- 编辑器默认结构化表单；切换 JSON 时保持同一语义模型。

### 4.5 流量治理

- IP 名单按黑名单、白名单、来源和状态分类展示。
- 编辑器支持结构化条目与 JSON 高级模式；明确展示规则作用范围。
- 无法读取 Redis/Nacos 时展示依赖异常，不展示空名单。

### 4.6 访问控制

- 分区展示授权资源、忽略 Token 规则和幂等 URI，禁止混合编辑。
- 资源详情展示路径、方法、属性摘要、来源和历史。
- 权限不足时页面可解释缺少的操作权限，但不暴露内部安全配置。

### 4.7 认证客户端

- 列表展示 clientId、授权类型、作用域、状态和更新时间。
- Secret 只显示“已设置”；编辑时提供“保持原值”或“设置新值”两种明确选择。
- 掩码占位符不得作为新 Secret 提交。

### 4.8 变更中心

- 默认按待处理优先排序，并支持状态、资源类型、对象和时间筛选。
- 详情展示基础版本、目标版本、语义差异、校验结果、发布记录、快照和 allowedActions。
- 差异按字段路径展示 ADD/REMOVE/REPLACE；敏感值只显示变化标记。
- 发布/回滚确认框必须再次展示环境、对象、风险摘要和影响范围。
- 执行中断后页面主动查询发布记录；不得直接提示失败或自动重发。

### 4.9 审计追踪

- 支持对象、动作、结果、操作人和时间范围筛选，并强制分页。
- 详情抽屉展示 requestId、对象、结果、脱敏摘要和关联变更。
- 不提供无边界全量导出，不展示配置正文、Token 或 Secret。

## 5. 通用状态组件

| 状态 | 展示要求 | 允许动作 |
| --- | --- | --- |
| 加载中 | 局部骨架或表格 loading | 允许取消当前筛选，不重复提交写操作 |
| 空数据 | 说明当前筛选无数据 | 清除筛选、按权限创建草稿 |
| 无权限 | 显示缺少的能力说明 | 返回或刷新权限 |
| 依赖不可用 | 显示依赖类型、可重试性、requestId | 重试、查看审计/依赖状态 |
| 数据漂移 | 三方差异与基线提示 | 返回编辑、重新取基线 |
| 执行中 | 阶段、开始时间、requestId | 查询状态，不允许重复发布 |
| 执行失败 | 失败阶段、脱敏摘要、可重试性 | 按 allowedActions 重试或回滚 |
| 待确认 | 明确结果未知而非失败 | 查询目标态、人工确认 |

## 6. 页面验收清单

- [ ] 导航、环境、权限菜单和页面标题层级符合本契约。
- [ ] 登录、概览、服务、网关、流量、访问控制、认证客户端、变更和审计页面齐备。
- [ ] 所有列表均有加载、空数据、无权限和依赖失败状态。
- [ ] 四个治理域均支持结构化表单、JSON 高级模式和服务端语义差异。
- [ ] 发布、回滚、漂移和未知执行结果具备独立交互。
- [ ] 浏览器持久化存储中不存在 Access Token 或 Refresh Token。
- [ ] Token、Secret、密码、敏感配置和审计摘要均经过脱敏。
- [ ] 页面深路由刷新可由同一个 admin-service JAR 正确返回 SPA。
- [ ] 旧版 Freemarker/原生 JS 只在新版验证完成并再次确认删除后退出。

## 7. 确认记录

- 信息架构：用户确认推荐的“能力工作区 + 统一变更中心”。
- 视觉样式：用户确认推荐 A“沉稳专业运维风格”。
- 使用模式：当前单管理员使用，不建设审批流。
- 发布方式：有权限管理员查看差异并二次确认后直接发布。
- 演进方式：旧版未上线，基于旧版直接修改；删除旧资源仍保留独立 Gate。
