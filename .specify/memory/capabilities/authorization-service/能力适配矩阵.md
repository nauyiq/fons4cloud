# 能力适配矩阵

> 文档层级：能力域适配索引
> 能力域名称：授权服务
> 能力域标识：authorization-service
> 文档状态：基线已建立
> 更新日期：2026-06-26

## 1. 适配范围

- 技术能力：OAuth2 授权、账号认证、Token 生成/刷新/吊销、Token 存储与内省、权限资源校验、认证服务暴露。
- 适配对象类型：认证方式、存储实现、服务暴露形态。
- 公共能力抽象：`AccountAuthenticationFacadeService`、`AuthenticationApplicationService`、`Oauth2ResourceOwnerBaseAuthenticationConverter`、`Oauth2ResourceOwnerBaseAuthenticationProvider`、`Oauth2ResourceOwnerBaseAuthenticationToken`、`OAuth2AuthorizationService`、`DefaultRegisteredClientRepository`、`DefaultOauth2AccessTokenGenerator`、`AuthPermissionService`。
- 不得作为标准能力的特定实现：Password/Email/SMS 三种授权模式、Redis Token 存储、Dubbo RPC 暴露、HTTP Token 端点、Opaque Token 内省。

## 3. 标准能力判定

| 结论 | 依据 | 适用范围 | 限制 |
| --- | --- | --- | --- |
| 自定义 Resource Owner 授权模式的 Base Converter/Provider/Token 可作为扩展标准骨架。 | Password/Email/SMS 三个实现均继承同一套 base 抽象。 | 新增类似验证码、第三方登录等自定义授权模式。 | 具体参数和凭证校验方式仍属于特定适配。 |
| `AuthenticationApplicationService` 可作为脱离 HTTP 上下文的认证应用服务标准骨架。 | RPC Facade 委托该服务完成认证、刷新、吊销。 | 内部服务认证调用。 | 具体暴露方式不限定为 Dubbo。 |
| `OAuth2AuthorizationService` 是 Token 存储标准契约，Redis 是当前实现。 | Spring Authorization Server 契约与 Redis 实现类。 | Token 保存、查询、删除。 | 不把 Redis 写成唯一可替代标准。 |
| HTTP Token 端点和 Opaque Token 内省是运行场景，不单独作为适配对象。 | 当前未发现多端点或多内省实现横向对比。 | 主文档和矩阵记录。 | 后续若出现多实现再拆分适配说明。 |
