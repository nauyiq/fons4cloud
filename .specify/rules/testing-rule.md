# 测试与验证规则

> 适用范围：fons4cloud 单元测试、自动配置测试、集成验证、构建检查与手动验证
> 生成依据：用户指定 `$fons4ai-generate-project-rules`、根 `pom.xml`、现有测试源码、`AGENTS.md`、代表性模块
> 规则状态：已有项目提炼

## 强制规则

- 行为测试规则：新增或修改可观察行为时，必须优先新增或更新自动化测试；无法自动化时必须记录原因、手动步骤和风险。
- BUG 复现规则：修复 BUG 前必须建立可复现信号；可自动化时先写失败测试，不可自动化时记录最小复现步骤。
- 测试位置规则：新增测试放在被测模块的 `src/test/java`，包路径与被测类保持对应，测试类以 `Test` 结尾。
- 测试命名规则：测试方法必须描述行为和条件，优先使用 `should...When...` 或等价清晰命名。
- 自动配置测试规则：新增 Spring Boot 自动配置时，必须优先使用 `ApplicationContextRunner` 验证 Bean 条件、默认实现和关键配置开关。
- 敏感信息测试规则：涉及密钥、token、密码、手机号、身份证、clientSecret、secretKey 的错误处理必须验证日志/异常/响应不泄露敏感值。
- 验证记录规则：交付时必须说明运行的测试命令、结果、未验证项和手动验证步骤。

## 推荐规则

- 优先写聚焦测试证明变更，不为小变更启动大范围慢集成测试。
- 优先使用 AssertJ 链式断言表达业务预期，避免只断言非空或无异常。
- 对外部依赖使用 Mock、Stub、Fake、`ApplicationContextRunner` 或反射注入隔离，不依赖真实生产服务。
- 对路径、时间、随机数、并发、缓存、MQ 和外部服务场景，使用可控输入降低不稳定。
- Maven 验证优先从受影响模块开始，例如 `mvn -pl <module> test`；跨模块依赖变更使用 `mvn -pl <module> -am test` 或构建检查。

## 禁止事项

- 禁止用手动验证替代可行的自动化测试。
- 禁止提交依赖真实生产账号、生产服务、真实密钥或不可重复环境的测试。
- 禁止为通过测试而削弱断言、删除关键测试、扩大跳过范围或隐藏失败。
- 禁止只跑全量构建替代有针对性的失败复现和回归测试。
- 禁止让测试修改受版本控制文件，除非已说明影响并获得确认。

## 例外机制

- 如果自动化测试不可行，必须记录不可行原因、手动验证步骤、预期结果、风险范围和后续补测建议。
- 如果测试需要外部服务、数据库、消息中间件或特殊环境，必须先说明依赖、配置和可能副作用。
- 如果验证命令因本地环境、依赖下载或历史工作区状态失败，必须保留关键错误信息并说明未验证风险。

## 待确认约定

- 是否建立模块级标准 Maven 验证命令清单。
- 是否引入 Testcontainers、嵌入式 Redis、嵌入式 MQ 或专用集成测试环境。
- 是否定义单元、集成、契约、持久化测试的目录或命名分层。
- 是否有团队 CI 必跑命令和失败处理流程。

## 验收检查

- [ ] 每个实现任务都有自动化或手动验证方式。
- [ ] 行为变更已新增或更新聚焦测试。
- [ ] BUG 修复包含复现、根因、回归验证和未验证风险。
- [ ] 自动配置变更覆盖默认 Bean、条件开关和冲突场景。
- [ ] 测试不依赖敏感数据、生产服务和不可控外部状态。
- [ ] 交付说明列出测试命令、结果、未验证项和手动验证步骤。
