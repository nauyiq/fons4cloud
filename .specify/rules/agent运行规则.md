# Agent运行规则

> 适用项目：fons4cloud
> 规则状态：已建立
> 更新日期：2026-07-01
> 依据来源：`AGENTS.md`、`.specify/memory/index.md`、根 `pom.xml`、已建模能力域文档、用户确认

## 项目适用范围

- 本规则适用于当前仓库内的源码、配置、知识库、SDD 产物和规则文件。
- 本项目按技术框架/基础设施项目处理，不抽象业务领域。
- 项目知识入口为 `.specify/memory/index.md`；能力域知识位于 `.specify/memory/capabilities/{capability-slug}/`。
- 已建模能力域包括 MQ 抽象与多中间件适配、授权服务、网关服务；其他能力仍按知识库索引状态处理。
- 本项目启用 Fons4AI 路由，涉及知识库、SDD、BUG 修复或项目规则时，优先使用对应 Fons4AI 技能。

## 核心原则

- 默认使用中文沟通、编写文档和交付说明。
- 修改代码前必须先理解需求，并完成必要的上下文阅读和影响面判断。
- 先调研再设计或修改；修改代码、配置、文档前必须读取相关上下文。
- 以项目事实为准，不凭空猜测业务逻辑、接口、字段、表结构、第三方 API、部署方式或生产配置。
- 优先遵循项目规范，包括 `AGENTS.md`、知识库、规则文件、源码约定和已有测试习惯。
- 优先遵循 `AGENTS.md`、`.specify/memory/`、`.specify/rules/`、源码和已有代码风格；若相互冲突，必须标记冲突并请求确认。
- 优先复用已有代码，包括项目内工具类、公共组件、抽象接口、自动配置、Facade、Provider 和 Adapter。
- 优先复用项目已有工具、组件、抽象、AutoConfiguration、Facade、Provider、Adapter 和公共模型，不重复造轮子。
- 删除文件、覆盖文档、大范围重构、修改数据库结构或改变公共契约前，必须先获得用户确认。
- 单个实现、单个配置样例、单个模块行为不得直接写成项目标准；除非来自公共抽象、横向对比、正式文档或用户确认。
- 对于较大新需求，先走 SDD：需求说明书、技术设计说明书、任务规划；任务规划生成后暂停等待用户确认执行。
- 对于 BUG、异常或回归失败，优先走 Fons4AI BUG 修复工作流。

## MCP与外部工具使用规则

- MCP、浏览器、数据库、网络、远程服务、包仓库、配置中心等外部能力只能作为当前会话工具使用，不能默认写成项目级事实。
- 未发现项目级 MCP 配置或团队 MCP 规范时，不生成 MCP 工具清单，不记录个人本机 MCP 名称、账号、连接串、内部地址或敏感返回内容。
- 使用外部工具前必须说明目的；涉及网络、远程认证、数据库、配置中心、集群或生产资源时，必须遵守权限边界并在必要时请求确认。
- 查询或读取到的外部结果只能作为证据来源之一；与源码、知识库或用户文档冲突时必须标记冲突。
- 不得把本地临时路径、个人环境变量、token、密码、连接串、数据库账号或敏感业务数据写入知识库、规则文件或交付说明。

## 输出要求

- 输出必须简洁、直接、可执行；优先给结论、影响范围、证据路径和下一步。
- 文档、规则、知识库和 SDD 产物默认使用中文标题和正文。
- 生成或更新知识库时，必须标明确认状态、证据来源、待确认事项和标准判定边界。
- 生成或更新 SDD 产物时，必须使用 `S1` 或 `S2`，产物默认位于 `spec/features/{yyyymmdd}/`。
- 生成 BUG 修复报告时，默认位于 `spec/bugfixes/{yyyymmdd}/{bug中文名}-BUG修复报告.md`。
- 交付前尽量运行项目或技能提供的校验脚本；未能运行时必须说明原因。
- 涉及文件变更时，最终说明必须列出主要文件、变更类型和验证结果。

## 禁止事项

- 不允许修改与当前需求无关的源码、配置、文档或知识库内容。
- 不允许引入新的技术框架，除非用户明确确认且已有技术栈无法满足需求。
- 不允许删除核心业务逻辑、公共能力骨架、接口契约或已验证知识。
- 不允许修改数据库结构，除非需求明确要求并经过用户确认。
- 禁止在证据不足时编造业务流程、接口契约、字段含义、表结构、配置值、第三方 API 或生产部署事实。
- 禁止编造接口、编造数据库字段、编造第三方 API。
- 禁止未经确认删除、覆盖或大范围重写用户已有内容。
- 禁止把授权服务、网关、MQ 等单个能力域的代表性实现写成全项目标准。
- 禁止把未建模或待确认能力写成已验证知识。
- 禁止把个人本机工具、MCP、临时命令输出或私有凭据写成团队规则。
- 禁止在未完成必要调研和澄清时直接生成正式 SDD 三件套或正式知识库。
- 禁止在任务规划生成后未经用户确认直接进入实现。

## 信息不足时的处理

- 信息不足时，先读取最小必要上下文：`AGENTS.md`、`.specify/memory/index.md`、相关能力域文档、相关源码/配置/测试。
- 对外部系统、远程服务、生产环境、数据库、MCP 和敏感资源默认只读；确需写入、删除、迁移或变更时必须先确认。
- 若关键需求含义、技术术语、数据语义、验收口径、兼容性、安全权限、迁移回滚或 SDD 等级存在歧义，必须先澄清。
- 若问题不阻塞主流程，可写入待确认事项，但不得写成已验证事实。
- 用户回复“按推荐”或“确认”时，只确认当前问题；除非用户明确说明“全部按推荐”，不得代替后续阻塞问题确认。
- 用户提供文档与源码不一致时，必须记录冲突、说明影响，并请求用户选择可信来源。
- 无法确认外部环境、生产配置、数据库结构或远程服务状态时，只记录为待确认，不反推结论。
